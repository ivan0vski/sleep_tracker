# Пуши на экран блокировки iOS

Как это устроено и как развернуть.

## Зачем вообще сервер

iOS **не даёт** веб-приложениям планировать локальные уведомления. `TimestampTrigger`
на Apple не существует. Единственный способ положить что-то на экран блокировки при
закрытом приложении — Web Push, а он по определению требует, чтобы кто-то снаружи
прислал пуш в нужную минуту.

Этот воркер — и есть тот «кто-то». Максимально тупой:

```
приложение (GitHub Pages)          Cloudflare Worker              iPhone
─────────────────────────          ─────────────────              ──────
считает расписание фаз
  ↓
[{ts, title, body}, ...]  ──POST /register──►  KV
                                                ↓
                                        cron * * * * *
                                        «есть моменты в этой минуте?»
                                                ↓
                                        шифрует RFC 8291 ──push──►  экран
                                                                    блокировки
```

Воркер **ничего не знает про фазы сна**. Вся логика остаётся в `js/notifications.js`,
на сервер уезжает уже готовый плоский список моментов на весь план. Поэтому времена
автоматически едут вместе с фазой, а дублировать расчёт в двух местах не нужно.

## Развёртывание (Node и wrangler не нужны)

Всё делается мышкой в панели Cloudflare — воркер написан одним файлом без зависимостей
специально для этого.

**1. Создать воркер**

Cloudflare Dashboard → Workers & Pages → Create → Workers → Create Worker.
Имя, например, `sleep-push`. Deploy.

**2. Залить код**

Edit code → выделить всё → вставить содержимое `worker.js` → Deploy.

**3. Создать KV**

Storage & Databases → KV → Create a namespace, имя `sleep-push`.

**4. Привязать KV и переменные**

Воркер → Settings → Bindings:

| Тип | Имя | Значение |
|---|---|---|
| KV namespace | `PUSH_KV` | `sleep-push` |
| Variable | `APP_URL` | `https://ivan0vski.github.io/sleep_tracker/index.html` |
| Variable | `VAPID_SUBJECT` | `mailto:твой@email` — реальный, push-сервисы отбраковывают мусор |
| Secret | `ADMIN_TOKEN` | любая длинная случайная строка |

`ADMIN_TOKEN` — общий секрет между приложением и воркером, его же вводишь
в настройках приложения. Без него `/register` и `/test` возвращают 401.

**5. Включить cron**

Settings → Triggers → Cron Triggers → Add → `* * * * *` (каждую минуту).

**6. Проверить криптографию**

Открой в браузере:

```
https://sleep-push.ТВОЙ-ПОДДОМЕН.workers.dev/selftest
```

Должно вернуть `{"pass": true, ...}`. Этот эндпоинт прогоняет шифрование на
официальном тест-векторе из RFC 8291 §5 прямо в рантайме Cloudflare — то есть
проверяет ровно тот код, который задеплоен. Если `pass: false`, пуши не поедут,
и разбираться надо здесь, а не на телефоне.

## Подключение iPhone

Обязательные условия: **iOS 18.4+** и приложение, **добавленное на домашний экран**.
Во вкладке Safari пуши не работают — это ограничение Apple, не приложения.

1. Открыть приложение в Safari → Поделиться → «На экран «Домой»».
2. Запустить **с домашнего экрана** (не из Safari).
3. Настройки → Пуши на телефон.
4. Вставить адрес воркера и `ADMIN_TOKEN` → Сохранить.
5. Включить «Подключить пуши» → выдать разрешение.
6. «Отправить тестовый пуш» — должен прилететь.
7. Настройки → Напоминания о распорядке → включить нужные шаги.

Список из четырёх галочек на экране «Пуши на телефон» показывает, какое условие
ещё не выполнено.

## Что происходит дальше

Приложение перезаливает расписание при каждом изменении плана, распорядка или
настроек напоминаний, и при каждом открытии. Заливается **весь остаток плана**
целиком, поэтому расписание не кончится, даже если не открывать приложение неделями.

## Бесплатный тариф

Считается впритык и с запасом:

- **KV writes: 1000/сутки.** Воркер намеренно **не пишет курсор каждую минуту** —
  окно вычисляется из `event.scheduledTime`, минуты идут встык, поэтому каждый
  момент попадает ровно в один запуск без состояния. Записи происходят только при
  `/register` (несколько раз в сутки).
- **KV reads: 100 000/сутки.** 1440 запусков × (1 list + 1 get на устройство) ≈ 3000.
- **Worker requests: 100 000/сутки.** 1440 cron-запусков.

## Ограничения, о которых стоит знать честно

- **Пропущенный запуск cron = потерянное напоминание.** Окно ровно одна минута и
  состояния нет. Cloudflare крайне редко, но пропускает запуски. Для будильника
  распорядка это приемлемо; для чего-то критичного нужен курсор в Durable Object.
- **TTL 180 секунд.** Если телефон офлайн дольше трёх минут, пуш отбрасывается,
  а не приходит с опозданием. Для напоминания «выключи экраны» опоздавшее
  уведомление хуже отсутствующего.
- **Сброс KV = потеря VAPID-ключей.** Ключи генерируются при первом обращении к
  `/key` и лежат в KV. Если namespace снести, ключи станут другими и все
  подписки придётся оформлять заново.
- **Подписку может отозвать сама система** (переустановка PWA, долгое неиспользование).
  Приложение это замечает при синхронизации и просит переподключить.

## Эндпоинты

| Метод | Путь | Авторизация | Назначение |
|---|---|---|---|
| GET | `/health` | нет | живость |
| GET | `/selftest` | нет | тест-вектор RFC 8291 §5 |
| GET | `/key` | нет | публичный VAPID-ключ (генерит при первом вызове) |
| POST | `/register` | Bearer | сохранить подписку + расписание |
| POST | `/unregister` | Bearer | удалить устройство |
| POST | `/status` | Bearer | сколько моментов запланировано и когда ближайший |
| POST | `/test` | Bearer | прислать тестовый пуш немедленно |
